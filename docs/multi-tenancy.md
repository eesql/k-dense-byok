# macOS 内网多租户首版方案

状态：首版已实现，用户于 2026-10-02 确认基本测试验证通过，[GitHub issue #1](https://github.com/eesql/k-dense-byok/issues/1) 已关闭为 completed；部署时默认关闭。正式规格见 [多租户访问规格](multi-tenancy-spec.md)，验收证据见 [验收矩阵](multi-tenancy-verification.md)，启动方法见 [部署说明](multi-tenancy-deployment.md)。

## 已确认范围

- 在 Mac mini 或 Mac Studio 上原生部署，通过内网邀请使用。
- 多租户模式作为默认关闭的部署开关，停止／重启后切换；关闭时沿用单用户流程并保留单独保存的租户数据。
- 新能力优先放入独立入口和模块，只增加必要的上游接入点，尽量减少结构改动与后续合并成本。
- 租户是实验室或团队；每个用户归属一个租户，租户拥有多个共享项目。
- 用户名密码登录，一次性邀请链接；平台管理员管理租户，租户负责人管理成员。
- 同一租户共享项目、聊天和自带模型访问，不引入私人项目或私人凭据。
- 每个项目明确选择 BYOK 或平台供给，失败后手动切换。
- BYOK 保留现有供应商 API Key／OAuth；平台供给首版接 OpenRouter。
- 平台管理员设置租户模型预算及并发上限；不做充值、支付、SSO 或邮件发送。
- Modal 等外部服务使用租户自带凭据。
- 首版不做执行环境隔离。容量设计参考为 20 人、5 个同时运行任务，实际容量实测。

## 信任前提

网页与 API 根据登录身份校验租户归属。Agent 的本机代码执行具有宿主机 OS 用户权限，目录划分和工作进程只管理运行状态，不构成安全隔离。

因此首版要求整台部署中的使用者互相信任：shell 可能读取其他租户的数据、供应商凭据或平台主 Key。模型网关提供调用归属、预算与并发管理，但无法约束取得主 Key 后绕过网关的直接调用。用户已确认这一部署前提。

## 最小实现

1. 增加默认关闭的多租户部署开关；开启时使用独立启动入口、管理服务与可选前端模块，复用现有项目后端。原有单用户启动方式保留，关闭时不初始化管理数据库或额外服务，不将租户数据暴露为单用户项目；开启失败不静默回退单用户模式。上游代码仅增加必要、明确且受模式约束的接入点，不全面重构核心或修改 vendored SDK。
2. 管理服务使用 Node 内置 SQLite 持久化租户、用户、邀请、登录会话、项目归属和平台用量。密码使用 Node `scrypt`，登录使用 HttpOnly cookie；邀请令牌与会话令牌仅保存摘要。内网部署入口使用 HTTPS。
3. 网页与 API 使用同源入口。服务端按已验证身份查询项目归属并选择后端；客户端传入的项目 ID 是资源选择，不是授权。跨租户或未知项目返回拒绝，不回退到其他工作区。
4. 每个项目由一个 macOS 原生 Node 工作进程运行现有 Kady 后端。工作进程使用独立项目根、固定项目 ID 与指定凭据来源，避免进程级 Pi runtime、环境变量及后台任务串用来源；仅绑定 loopback，由管理入口转发。
5. BYOK 工作进程共享租户级 Pi 认证与设置目录；平台工作进程使用分开的认证与设置目录，避免已有 OAuth 或自带 Key 覆盖平台供给。项目文件、聊天与科研记录保持原有格式。
6. 管理服务串行保存租户环境配置。受管理工作进程只加载指定配置文件，不加载仓库根或旧版 `.env`，也不继承其他租户或平台主凭据。
7. 平台模型网关根据工作进程令牌确定租户及项目，再调用固定 OpenRouter 上游；不接受客户端指定任意上游。支持流式响应、费用估算与持久化、并发控制和预算耗尽后的新调用拒绝；未知价格或结算不确定时明确报告，不默认为零。
8. 前端增加登录／邀请加入、租户成员管理、平台租户与额度管理，以及项目模型供给选择。现有聊天、SSE 重连、文件预览、下载、Office、OAuth 与后台回调均经一致的归属校验。
9. 浏览器缓存按用户与租户分区，退出或账号切换时清理活动状态。移除成员或停用账号后立即使其登录会话失效；既有科研任务属于共享项目，不因该成员失去访问权限而自动终止。

## 已确认的运行规则

- 项目仍有运行中的聊天、子代理、远程任务或后台工作时，拒绝切换模型供给。暂停调度并确认空闲后重建工作进程，保留磁盘上的聊天与科研记录。
- 修改租户共享凭据时，空闲工作进程重载；忙碌工作进程完成当前工作后重载，在重载前拒绝新的模型任务。明确显示待生效状态，不通过并发修改全局环境变量切换凭据。

## 验收

- 覆盖开关未设置、关闭、开启和无效配置；关闭时维持原有单用户行为，重新开启保留租户管理状态，模式关闭不公开租户数据。
- 通过改动范围审阅确认独立模块和少量必要接入点，通过现有回归检查确认上游单用户工作流兼容。
- 两个租户并发使用时，网页／API 无法跨租户列出或修改项目、聊天、文件和设置；所有 header、query、URL 参数入口一致校验。
- 普通成员无法通过管理 API 修改租户归属、成员角色或平台额度；邀请不能重复使用，停用与退出后的会话失效。
- BYOK 与平台项目并发时，主代理、子代理和后台任务使用各自选择的模型来源；配置不会写入单用户安装的 `.env`。
- 供给切换保留项目与历史；忙碌切换被拒绝；共享凭据更新按上述规则生效。
- 平台流式调用、预算耗尽、并发超限、请求中断及服务重启后用量处理可验证；显示估算限制，不承诺供应商账单硬上限。
- 聊天、上传、预览、下载、Office、OAuth 与调度完成基本集成验证；测试不调用真实付费供应商。
