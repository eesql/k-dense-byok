# Kady：macOS 内网多租户访问规格

状态：首版实现与基本验收完成，用户于 2026-10-02 确认验证通过；[issue #1](https://github.com/eesql/k-dense-byok/issues/1) 已关闭为 completed。代码交付与提交记录见 [代码交付 issue #2](https://github.com/eesql/k-dense-byok/issues/2)。

## Problem Statement

一个实验室或团队希望让多人通过内网浏览器共同使用部署在 Mac mini 或 Mac Studio 上的 Kady，而多个实验室或团队需要在网页和 API 中分别管理自己的项目、聊天、文件、模型访问与平台额度。

当前 Kady 面向单个可信 OS 用户：服务器共享一个访问 Token，项目 ID 只选择工作区，不代表成员授权；供应商凭据与 Pi 模型运行时是进程级共享状态。直接把现有服务器开放给多人，会让所有人共享管理能力，也无法可靠地按项目并发使用不同凭据来源。

首版使用者是互相信任的内部人员。用户明确选择不做执行环境隔离，因此本规格解决身份、网页／API 归属校验、并发凭据路由及平台供给管理；不承诺 Agent 本机代码执行的跨租户保密或安全隔离。

## Solution

提供通过部署开关启用的 macOS 原生多租户模式，默认关闭。关闭时沿用现有单用户启动与使用流程；开启时，平台管理员创建实验室／团队租户并分配平台模型预算与并发上限，租户负责人通过一次性链接邀请成员，成员使用用户名密码登录，共同使用本租户项目与聊天。

每个项目明确选择租户自带模型访问（BYOK）或平台供给模型访问。BYOK 保留现有供应商 API Key 与受支持 OAuth；平台供给首版接 OpenRouter，按租户汇总模型用量。调用失败不会自动切换供给，运行中的项目也不能更换供给来源。

复用现有科研工作流，通过同源入口访问聊天、文件、预览、Office 和设置。新增能力集中在独立入口、管理服务和可选界面模块中，现有上游代码仅增加必要、明确且受模式约束的接入点，以减少后续合并上游更新的成本。保留单用户启动方式与已有数据格式；新模式使用单独的管理状态和配置，不自动迁移或覆盖现有本机数据与凭据。

## User Stories

1. 作为部署管理员，我希望在 Mac mini 或 Mac Studio 上原生启动多租户模式，以便复用现有 macOS 设备。
2. 作为部署管理员，我希望不依赖 Docker 或虚拟机，以便降低首版部署成本。
3. 作为部署管理员，我希望原有单用户启动方式继续可用，以便现有使用方式不受影响。
4. 作为部署管理员，我希望新模式与原有本机配置分别保存，以便试用新模式时不覆盖已有项目和凭据。
5. 作为部署管理员，我希望明确知道本机 shell 没有跨租户隔离，以便仅邀请互相信任的内部人员。
6. 作为平台管理员，我希望通过部署时的本机初始化建立第一个管理员，以便无需公开注册入口。
7. 作为平台管理员，我希望创建并命名实验室／团队租户，以便分别组织不同协作团队。
8. 作为平台管理员，我希望为租户指定负责人，以便将成员管理交给对应团队。
9. 作为平台管理员，我希望查看租户与成员状态，以便管理内网服务的使用者。
10. 作为平台管理员，我希望停用用户账号，以便及时撤销其网页和 API 访问。
11. 作为平台管理员，我希望配置平台 OpenRouter 供给，以便没有自带模型凭据的租户也能使用模型。
12. 作为平台管理员，我希望配置每个租户的平台模型预算，以便控制正常经网关发生的模型支出。
13. 作为平台管理员，我希望配置租户并发上限，以便避免单个团队占满共享服务资源。
14. 作为平台管理员，我希望查看按租户与项目归属的模型用量，以便识别额度消耗来自哪里。
15. 作为平台管理员，我希望预算设置与已记录用量在服务重启后保留，以便不会因重启恢复已用额度。
16. 作为租户负责人，我希望生成有有效期的一次性邀请链接，以便邀请同一团队的成员加入。
17. 作为受邀用户，我希望通过有效邀请设置用户名和密码并加入指定租户，以便开始使用团队项目。
18. 作为租户负责人，我希望已使用或过期的邀请不能再次加入用户，以便链接不能无限扩散成员访问。
19. 作为租户负责人，我希望查看并移除本租户成员，以便管理团队人员变动。
20. 作为租户负责人，我希望只能管理所属租户的成员，以便不会通过管理 API 修改别的团队。
21. 作为租户成员，我希望使用用户名密码登录，以便拥有明确的访问身份。
22. 作为租户成员，我希望登录错误不会暴露密码或敏感凭据，以便账户信息不会进入页面和日志。
23. 作为租户成员，我希望退出后原登录会话不能继续访问，以便共享浏览器使用时可以结束自己的访问。
24. 作为租户成员，我希望账号被停用或成员身份被移除后立即失去访问，以便成员管理决定即时生效。
25. 作为租户成员，我希望切换账号时清理原用户的活动页面和缓存，以便不会在新身份下显示上一位用户的工作区。
26. 作为租户成员，我希望查看并创建本租户项目，以便分别组织多个科研课题。
27. 作为租户成员，我希望共同访问本租户项目的聊天、文件和科研记录，以便团队能够协作。
28. 作为租户成员，我希望修改或猜测项目 ID 不会通过网页／API访问其他租户项目，以便正常访问遵循租户归属。
29. 作为租户成员，我希望访问未知或已删除项目时得到明确错误，以便请求不会悄悄落入默认工作区。
30. 作为租户成员，我希望保留现有聊天、历史重开和流式重连，以便多人部署仍能完成持续科研任务。
31. 作为租户成员，我希望上传、下载和预览文件均使用同一登录身份，以便科研文件操作不需要暴露后端访问 Token。
32. 作为租户成员，我希望继续使用 Office 打开、编辑和保存，以便已有文档工作流继续可用。
33. 作为租户成员，我希望采访表单、权限请求和停止／引导任务操作继续可用，以便能够控制现有 Agent 工作流。
34. 作为租户成员，我希望团队自带 API Key 与受支持的供应商 OAuth 可以继续使用，以便保留 BYOK 能力。
35. 作为租户成员，我希望本租户的共享模型设置和凭据更新对相关项目一致生效，以便不同项目不会长期停留在不一致配置。
36. 作为租户成员，我希望每个项目显示当前模型供给方式，以便知道调用使用自带还是平台供给。
37. 作为租户成员，我希望自带与平台项目并发时各自使用已选来源，以便不会串用凭据或错误归属支出。
38. 作为租户成员，我希望模型失败时得到原有错误并自行决定切换，以便系统不会自动消耗另一方额度。
39. 作为租户成员，我希望主代理、子代理与后台任务遵循相同的项目供给选择，以便委派工作不会使用另一套凭据。
40. 作为租户成员，我希望运行中的项目无法切换模型供给，以便不会中断任务或在任务中途改变费用来源。
41. 作为租户成员，我希望在调度暂停且项目空闲后切换供给并保留历史，以便不用新建项目来更换模型访问。
42. 作为租户成员，我希望共享凭据更新后看到待生效状态，以便知道哪些任务仍使用已有配置。
43. 作为租户成员，我希望忙碌项目完成当前工作后再重载凭据，并在此前拒绝新模型任务，以便避免切换过程产生凭据竞态。
44. 作为租户成员，我希望通过平台供给继续收到模型流式响应，以便聊天交互体验保持一致。
45. 作为租户成员，我希望平台额度耗尽或并发已满时得到明确拒绝原因，以便知道应等待还是联系管理员。
46. 作为租户成员，我希望费用无法确定时明确显示估算或未结算状态，以便不会把缺失信息误认为零费用。
47. 作为租户成员，我希望在服务重启后继续查看已保存的项目与历史，以便持久记录不依赖工作进程存活。
48. 作为租户成员，我希望后台工作和供应商 OAuth 回调仍归属正确的租户与项目，以便无人值守任务不会路由到别人的工作区。
49. 作为租户成员，我希望继续使用自己团队配置的 Modal 等外部服务，以便多租户模式保留已有科研计算能力。
50. 作为租户成员，我希望移除成员不会自动终止该成员启动的共享科研任务，以便团队仍可接续已有工作。
51. 作为普通成员，我希望无法通过管理 API 改动成员角色、项目租户归属或平台额度，以便管理职责有明确边界。
52. 作为平台管理员，我希望主 Key 不通过正常网页、管理响应或工作进程配置下发给租户，以便正常模型调用由统一网关管理。
53. 作为部署管理员，我希望请求中断、模型调用失败和工作进程退出后正确释放并发占用，以便服务不会因残留占用永久拒绝任务。
54. 作为维护者，我希望可以不连接真实付费供应商就验证整个访问流程，以便回归测试可靠且不会产生费用。
55. 作为部署管理员，我希望通过默认关闭的部署开关启用多租户模式，以便相同安装可以按需选择单用户或团队使用。
56. 作为部署管理员，我希望关闭多租户模式后保留管理数据但不在单用户模式中开放它们，以便之后可以重新启用且不意外公开租户资料。
57. 作为维护者，我希望多租户能力集中在独立模块并只通过少量接入点连接上游，以便后续合并上游更新时减少结构冲突。
58. 作为单用户使用者，我希望未开启多租户模式时不出现登录要求、管理界面或额外管理服务依赖，以便原有启动和科研流程继续可用。

## Implementation Decisions

- **部署模式**：使用默认关闭的部署开关，显式开启时启动独立多租户入口，复用 Next.js 前端与现有 TypeScript／Pi 后端。首版运行于 macOS，不增加 Docker、VM 或独立 OS 账号要求；保留现有单用户入口。
- **开关生命周期**：开关在启动时解析，通过受控停止／重启切换模式，不提供浏览器中的即时认证降级开关。关闭时不启动管理服务／模型网关、不加载其专有运行依赖、不创建管理数据库、不显示多租户页面；继续遵循原有单用户认证策略。关闭保留租户管理数据且不将其映射到单用户项目目录，重新开启使用原有管理状态。显式开启但配置无效或管理启动失败时报告错误并停止，不自动退回单用户服务。
- **上游兼容约束**：优先新增独立管理模块、启动入口和前端可选模块，复用现有后端 API 与数据格式；仅对启动分流、受管理配置、固定项目选择及必要的任务准入／状态检查增加小而明确的接入点。模式相关改动限定在启用或受管理工作进程路径，不全面改写 Pi 运行时、现有 scope、项目存储或科研工具，也不修改 vendored Pi／扩展包来实现租户管理。必须保留修复真实授权和凭据竞态所需的检查，不能为追求少改文件而省略正确性。
- **领域归属**：租户是实验室／团队，项目归属一个租户，普通用户归属一个租户。平台管理员承担跨租户管理职责；租户负责人可管理本租户成员，成员共享本租户科研项目。
- **管理状态**：采用 Node 内置 SQLite，保存租户、用户及角色、邀请、登录会话、项目归属与模型供给、预算、并发配置、平台调用及结算状态。用数据库事务和约束处理一次性邀请消费、身份归属与用量更新。
- **账号初始化**：第一个平台管理员通过受控的本机初始化创建。内网不提供开放注册；管理员与负责人通过角色允许的管理操作创建邀请。邀请有效期有界，单次使用，校验和消费保持原子性。
- **登录**：密码使用带独立随机盐的 Node `scrypt` 哈希；会话和邀请令牌使用密码学随机值，持久层仅保存令牌摘要。登录 cookie 使用 HttpOnly、SameSite 及生产 HTTPS 下的 Secure；退出、停用和成员移除使会话失效。登录及邀请入口设有限速，变更请求校验受信来源以防 CSRF。
- **授权入口**：网页和 API 采用同源入口。入口从已验证会话读取身份与租户，查询资源归属后才选择工作进程。客户端的租户字段、项目选择、访问 Token 或 cookie 都不能自行提升权限。
- **访问合同**：未登录或会话失效返回 401；已登录但角色不允许管理操作返回 403；未知或属于其他租户的项目资源返回一致的 404；忙碌时切换供给或配置尚未生效返回 409；模型预算耗尽返回 402；超过明确并发上限返回 429。业务失败响应携带稳定原因及用户可理解的信息，不能与供应商认证失败混淆。
- **项目选择一致性**：所有 header、query、cookie、URL 参数和请求体中的资源引用都须经过归属校验；有冲突的选择应拒绝，不能利用一个已授权项目为另一个项目的请求背书。受管理模式不执行未知项目到默认项目的读取回退。
- **工作进程**：每个项目使用一个原生 Node 后端进程，固定项目 ID、项目根和供给来源；后端只绑定 loopback，经管理入口转发。用现有 Pi、文件与任务实现处理工作，不在请求之间切换全局环境变量。项目根只包含该项目，启动恢复与调度枚举不会重复接管其他项目。
- **运行状态与安全边界**：独立工作进程用于避免模型 runtime 和环境快照串用，不能宣称为执行安全隔离。所有 Agent 代码仍具有宿主机 OS 用户权限；管理员和所有租户必须属于互相信任的内部使用者。
- **BYOK 配置**：BYOK 工作进程直接共用同一租户的规范 Pi 认证与设置目录，允许团队共享 OAuth、默认设置、用户级技能与连接器。避免以不同软链路径共享认证文件，以保留 SDK 的跨进程锁语义。
- **平台配置**：平台工作进程使用与 BYOK 分开的认证／设置目录及项目访问令牌。已有自带 API Key 或 OAuth 不得覆盖平台来源；平台项目只能使用受支持的平台模型供给，不能通过正常设置 API 覆盖平台主 Key 或预算。
- **凭据保存**：管理服务成为租户共享环境配置的唯一串行写者。工作进程只加载指定的受管理配置，禁止隐式加载单用户仓库配置或继承无关供应商凭据。现有环境值与模型配置验证继续生效；凭据不得进入日志、错误或普通响应。
- **凭据生效**：更新后将相关工作进程标记为待重载，先阻止新的模型工作进入，再检查运行状态。空闲进程重载；忙碌进程完成现有工作后重载并恢复接收任务。OAuth 流程在正确租户范围内运行，已完成授权通过共享认证存储与重载策略生效。
- **供给切换**：切换只允许在项目无活动聊天、系统运行、前台／分离子代理、非终态远程任务或科研后台工作，且调度已暂停时进行。先禁止新任务进入，再检查空闲、保存来源并重建进程，避免检查与新任务启动竞态；重建失败显示不可用或失败状态，不静默转用另一来源。
- **后台工作**：系统发起的调用、定时任务、子代理与内部回调继承项目供给和归属。平台预算在模型网关而非仅在浏览器触发路径检查；已有项目预算与 Modal 的估算／预约机制保留各自语义。移除成员撤销访问，不自动停止共享项目任务。
- **模型网关**：平台主 Key 仅在管理服务／模型网关中配置，通过项目访问令牌解析租户与项目。上游固定为 OpenRouter，转发有界且受支持的模型请求及流式响应，不接受任意上游 URL、其他租户身份或供应商主凭据覆盖。此凭据分配方式不承诺阻止同 OS 用户 shell 直接读取主 Key。
- **额度语义**：租户平台模型预算按管理员设置的累计模型支出上限管理，汇总该租户所有平台项目；更改预算不清空既有用量。BYOK 模型支出和租户自带 Modal 支出不消耗平台模型预算，仍保留原有项目账本。不得把网关模型费用再次加到项目记录后重复计算同一支出。
- **并发语义**：租户的 Agent 任务上限统一覆盖不同供给的受管理项目及后台任务入口；模型网关同时控制平台模型请求并发，防止子代理或多请求绕过平台请求限制。Agent 任务和模型 HTTP 请求是不同计数单位，配置及界面明确标示。首版按全站最多五个同时运行的 Agent 任务作为初始容量参考，实际能力需实测；不用这一数字假设机器能并行五个任意重计算脚本。
- **费用与异常**：在新平台调用准入时检查已记录支出与未结算调用，结束后根据可获得用量及价格持久化结算；对超时、断流和重启遗留的已提交调用保留明确的未结算状态。无价格或无法安全判断是否还有额度时不以零成本准入。供应商自身的拒绝、流式终止和费用缺失继续准确传达。
- **资源访问**：统一转发聊天流、重连、文件二进制响应、预览、下载、Office 和供应商 OAuth。保留已有 Origin／Host 校验、原始文件内容限制、路径与符号链接验证、Office 修订校验以及其他防止数据损坏的检查。供应商 loopback 回调留在所属授权流程内，不要求供应商带用户 cookie；管理授权流程的 API 仍校验身份。
- **前端**：增加登录与邀请加入页面、角色允许的租户／成员／平台额度管理界面，以及项目供给选择和待生效状态。身份和角色由服务端返回；浏览器状态按用户及租户分区，退出或账号切换清理活动状态，迟到的旧身份响应不得恢复旧工作区。
- **兼容与重启**：聊天、科研记录与项目文件沿用既有格式，管理服务重启不清空身份、归属和预算。普通活动聊天在后端重启后仍遵循现有不可续跑限制；仅对已有持久化恢复能力的任务按既有规则恢复，不承诺任意工作自动续跑。首版不自动移动单用户历史到任何新租户。

## Testing Decisions

- 用户已确认以**登录后的同源 HTTP/API 入口**作为主要测试边界。测试从公开请求及结果验证行为，不断言内部私有函数、目录拼装细节、特定进程类或 SQL 实现。
- 复用现有 Vitest 与 Fastify 请求注入模式验证管理入口，不额外搭建一套测试框架。既有认证钩子、项目 scope、请求来源与 Office 路由测试是先例；多租户入口可以依赖测试供应商，仍走真实登录、授权和转发处理。
- 以两个租户、不同角色与 BYOK／平台项目覆盖完整授权矩阵，验证列表、详情、修改、历史、文件、下载、Office、OAuth 管理和后台控制。对 header、query、cookie、URL 参数、冲突选择、未知项目与已删除项目验证失败行为一致。
- 覆盖首次管理员初始化、邀请有效期、并发消费邀请、重复邀请消费、登录、退出、会话过期、停用与成员移除，以及管理角色越权。检查敏感值不进入公开响应、请求日志或错误信息。
- 通过实际 loopback HTTP 验证 SSE 增量转发、断开、重连与二进制下载；请求注入用于有限响应，避免只凭收集完整响应的测试证明流式行为。
- 补一组真实项目工作进程的集成检查，验证两个来源并发时主代理、子代理与后台调用的凭据和归属；不以只 mock 环境构造的单测证明真实 runner 没有串用配置。
- 复用现有真实 Pi 认证集成测试模式：SDK 和本机回调真实运行，供应商 token 交换与付费请求由本地模拟上游替代。任何测试意外调用真实外部供应商应失败。
- 在主要 HTTP 边界验证供给切换的忙碌拒绝、暂停调度、切换与新任务启动竞态、空闲重建、重建失败，以及聊天历史和文件保留。测试活动集合包含分离子代理、远程任务和科研后台工作，不能只检查主聊天。
- 在主要 HTTP 边界验证共享凭据的待生效状态、新任务阻止、空闲立即重载和忙碌完成后重载；验证受管理配置不会读取或覆盖单用户配置。
- 用可控模拟 OpenRouter 响应验证正常用量、流式用量、失败、未知价格、额度耗尽、跨项目累计、并发超限、断流、重复结算和重启未结算调用。通过重启服务后再次请求验证持久预算，而非只检查内存计数。
- 浏览器仅补登录／邀请、角色界面、项目供给选择、账号切换缓存清理及聊天／文件／Office 的关键流程。复用已有前端组件与工作区持久化测试，避免逐个复制所有已有界面测试。
- 从启动与公开请求边界覆盖开关未设置、关闭、开启与无效配置：关闭时继续使用单用户项目读取、认证、凭据保存和界面，且不创建管理数据库或运行额外管理服务。避免把受管理模式的无回退规则错误施加到既有本机模式。
- 验证模式经过停止／重启后保留租户数据，关闭时该数据不通过单用户服务暴露，重新开启恢复管理状态；显式开启失败不得启动未受管理的替代服务。上游结构兼容通过改动范围审阅与现有回归检查确认，不以文件数量断言代替行为测试。
- 所有文件、管理数据库、认证目录和供应商模拟均使用测试临时状态；不读写真实用户凭据，不运行真实付费调用。规格交付阶段只验证文档结构与决策一致性，不宣称功能测试已通过。

## Out of Scope

- Docker、虚拟机、独立 OS 用户、文件系统／网络／进程安全隔离，以及面向互不信任租户的托管服务。
- 公网开放注册、SSO、邮件发送、多租户成员身份、私人项目、私人聊天和私人凭据。
- 支付、充值、订阅售卖、供应商发票结算或严格供应商账单硬上限；月度预算重置与商业配额套餐。
- 平台托管供应商 OAuth，平台供给接入 OpenRouter 之外的供应商，以及模型失败后自动切换供给。
- 平台统一供给 Modal 或其他外部服务；任意脚本的 CPU、内存、磁盘、网络和外部付费调用的硬配额。
- 多机调度、水平扩展、高可用、任意运行中聊天跨重启续跑、自动迁移现有单用户项目。
- 活动任务中途切换供给、修改全局环境以即时切换并发请求凭据，或通过前端隐藏按钮代替服务端授权。
- 浏览器中即时开启／关闭全站认证或在服务运行中自动切换部署模式；全面重构上游核心架构、修改 vendored Agent SDK，或为多租户能力强制迁移既有单用户数据。

## Further Notes

- 用户已确认全部首版边界、全站互相信任前提、忙碌项目切换规则和共享凭据生效策略，并追加默认可关闭的多租户开关及尽量减少上游结构改动的要求。首版实现与本地验证已完成，证据见 [验收矩阵](multi-tenancy-verification.md)。
- 领域术语沿用已确认的租户、项目、平台管理员、租户负责人、租户成员、BYOK 与平台供给。四项 ADR 分别记录双模式模型供给、团队租户边界、macOS 本机执行前提，以及可关闭的独立扩展方式。
- 模型预算是正常网关调用的管理机制，费用按可获得信息估算；同 OS 用户取得平台主 Key 后绕过网关的调用不在其控制范围内。界面与部署说明不得使用“完全隔离”或“绝对不超支”等描述。
- 20 人、五个同时运行 Agent 任务是容量设计参考，不是已验证的 Mac 硬件承诺。成员数、Agent 任务并发与模型请求并发应分别解释。
- 受管理启动需要确认所用 Node 版本具备内置 SQLite；沿用项目支持的 Node 版本要求和现有开发工具，不引入新的数据库服务。
- 本规格按 `to-spec` 技能生成，测试入口已获用户确认。发布目标为已配置的 `eesql/k-dense-byok` GitHub Issues，分流标签为 `ready-for-agent`；配置采用默认五标签和单上下文领域文档布局。
